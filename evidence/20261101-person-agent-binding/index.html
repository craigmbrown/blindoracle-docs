Verify it without us

Everything below works from a laptop with curl, python3 and the opentimestamps-client. Steps 3 and 4 also need web3 (pip install web3) or any Ethereum tool that can make an eth_call.

1. The run log and the brief existed by block 53375797 on Base

sha256sum checkpoint.preimage            # must print the run digest above
python3 - <<'PY'
import hashlib
h=hashlib.sha256()
for n in ("run.jsonl","asset.md"):
    h.update(n.encode()+b"\0"+open(n,"rb").read()+b"\0")
print(h.hexdigest())                      # same digest, recomputed from the two files
PY
curl -s https://mainnet.base.org -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_getTransactionByHash","params":["0xf53be042c54310ac10fed3b90b36fdd069e60fb6f508be5c91a10108774577a4"]}' \
  | python3 -c "import sys,json; t=json.load(sys.stdin)['result']; print(t['input'], int(t['blockNumber'],16), t['from']==t['to'])"
# input == 0x + run digest, block 53375797, True

2. The same bytes are stamped into Bitcoin

3. The verified person's wallet signed the grant

Each grant in grants.json carries message and signature. The wallet is a Coinbase smart wallet, so the check is ERC-1271 on Base: hash the message the EIP-191 way and ask the wallet contract whether the signature is valid. The magic return value is 0x1626ba7e.

python3 - <<'PY'
import json
from web3 import Web3
from eth_account.messages import encode_defunct, _hash_eip191_message
w3=Web3(Web3.HTTPProvider("https://mainnet.base.org"))
g=json.load(open("grants.json"))["4a650c09252afa2d5139562e66a01ade"]
digest=_hash_eip191_message(encode_defunct(text=g["message"]))
abi=[{"name":"isValidSignature","type":"function","stateMutability":"view",
      "inputs":[{"name":"hash","type":"bytes32"},{"name":"signature","type":"bytes"}],
      "outputs":[{"name":"","type":"bytes4"}]}]
c=w3.eth.contract(address=Web3.to_checksum_address(g["person_wallet"]),abi=abi)
print(c.functions.isValidSignature(digest,bytes.fromhex(g["signature"][2:])).call().hex())  # 1626ba7e
PY

What this proves: the wallet's owner key signed exactly this message. What it does not prove: that a human was present. The grant record says owner_kind: key for that reason.

PY
# expect kind 30013 and tag ["d","63b7f3e8c5f7"] from each relay; the event content carries content_sha256
Known defect, found by an independent re-check and logged: the event for job 9fc2233c-d5e carries a hash taken before release with a different serialisation, so it does not match that job's receipt hash. The events for 63b7f3e8c5f7 and 8d5d345a5408 do.

7. Who judged the deliverables

The four verdicts per job in witness_attestations.json come from BlindOracle's own witness pool, provided by the marketplace on every judgment job: integrity is a deterministic hash check; substance, consistency and grounding are scored by models from three different vendors that are never told what the score will be used for. It is part of what the fee buys. Outside agents can enrol as advisory witnesses. A verdict is a judgement and can be wrong; the SPLIT verdict on 78428f2c-2ca is kept in the pack for that reason.
